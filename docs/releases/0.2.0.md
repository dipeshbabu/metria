# Metria 0.2.0

Metria now provides one installation for inference-change verification and KV
Fidelity methods. The package remains Alpha: qualification applies to the
explicit runtime/model/hardware contracts below, not arbitrary inference stacks.

Install with Python 3.10–3.14:

```bash
python -m pip install metria==0.2.0
metria --version
metria demo --case pass --output demo-pass
metria fidelity --help
```

The base wheel keeps zero runtime dependencies. Install native engines and model
files separately in their qualified environments.

## Qualified workflows

| Change | Evidence and preparation |
| --- | --- |
| llama.cpp CPU threads | Pinned model/provider and native applied-thread readback |
| llama.cpp CPU build | Independently qualified provider binaries; `prepare-llamacpp-build` |
| GGUF Q8_0 weights | Native conversion, actual mixed tensor storage and unchanged tokenizer/model controls; `prepare-gguf-quantization` |
| vLLM prefix cache | Pinned 0.30.0 CPU/CUDA wheels, observed cache state/hits and reset boundaries; `prepare-vllm` |
| vLLM CPU runtime stack | Isolated pinned 0.29.0+cpu and 0.30.0+cpu environments, native CPU placement and shared workload; `prepare-vllm-upgrade` |
| vLLM serving concurrency | One versus two in-flight requests at fixed engine capacity, native streaming and allocator/KV observations; `prepare-vllm-serving` |

Preparation commands use the `metria recipe` prefix. Each study then runs through
`metria verify study.json --output evidence`, with retained reference/candidate
records, canonical JSON and a Markdown report. Native qualification records name
their executed source revisions and wheel hashes; they are maintainer contract
checks, not production benchmarks.

## Decisions and measurements

Task checks now distinguish exact text, nonempty output and strict JSON-object
structure from token-trajectory agreement. Explicit policies can combine task
pass rates, observed reference repeatability and compatible systems measurements.
Missing evidence and invalid comparisons cannot become policy PASS.

Cold-process latency, loaded-engine request latency, and local streaming metrics
have distinct methods. Serving reports include first-token delivery, individual
token intervals when available, decode rate, batch token/request throughput,
native worker CUDA allocator peaks and allocated KV storage. Coalesced token
chunks do not produce invented per-token intervals. Local serving measurements
exclude HTTP/network overhead; PyTorch memory measurements exclude other
processes and non-PyTorch allocations.

`metria pilot record` binds keep/reject/inconclusive decisions and setup friction
to checked evidence files. Maintainer validation and participant feedback retain
separate provenance. Public representative task inputs are available in the
repository; actual participant feedback remains outstanding.

The retained maintainer pilot passed its literal-output workload and correctly
rejected the broader task and truncated-generation cases under unchanged task
criteria. All three had exact token agreement, while task pass rates were 100%,
50%, and 16.7%. These are task-contract observations on a small model, not external
user feedback or production performance evidence.

## Migration and remaining scope

- Use `metria.fidelity` and `metria fidelity` for the unified fidelity tools.
  The source-only `kv_fidelity` compatibility bridge retains old imports during
  migration. There is no separate KV Fidelity publication in this release.
- Saved report schemas and numerical method identities are preserved. Existing
  `manifest.json` aliases remain; prefer canonical `verification.json`.
- Regenerate recipes with the preparation command for their intended change.
  Qualified profiles require exact variation paths and fixed controls.
- TurboQuant Reference remains source-only research software pinned by Git
  revision. Its presence does not qualify experimental production kernels.
- Positive FP8 KV-cache qualification awaits a supported GPU. The existing GTX
  1650's confirmed incompatibility produces an actionable preflight rejection;
  automatic-cache CPU/CUDA paths remain qualified.
- External participant feedback has not been fabricated or substituted with CI
  results. It remains separate work after the maintainer pilot.
