# Metria 0.1.3

This Alpha patch release fixes evidence-file publication and numeric input
validation, updates vulnerable dependencies, and strengthens release checks.
Verification profiles, saved-report schemas, and numerical method identities
retain their existing scope.

```sh
python -m pip install metria==0.1.3
metria --version
metria demo --case pass --output demo-pass
```

The base package remains dependency-free and supports Python 3.10–3.14. Native
backend extras and the development workspace require Python 3.11 or newer so
they can use patched dependencies. The Python 3.10 core has its own audited,
locked compatibility environment and retains its required CI gate.

## Fixes

- Completed evidence files are published without replacing an existing file,
  dangling symlink, or a destination created by a competing writer. Publication
  failures preserve completed records and do not produce a success manifest.
- Oversized integer metrics are rejected as invalid evidence rather than
  raising an uncaught overflow error. Process deadlines reject overflowing
  integers, booleans, strings, and null values before launching a child.
- Markdown validation excludes ignored caches while checking tracked files,
  new author documents, and missing local targets.
- Windows process tests account for containment-helper startup while retaining
  bounded deadlines and checks that descendants are cleaned up.

## Security and maintenance

The shared lockfile uses filelock 4.2.7 and setuptools 84.2.1. Published native
extras require filelock 4.2.1 or newer; build backends require setuptools 84.1.0
or newer. These floors address the ten remaining dependency advisories reported
against the previous lockfile. Required CI audits both the full workspace and
the isolated Python 3.10 compatibility dependencies.

Dependency and pinned GitHub Actions updates have been reviewed and merged.
The README now leads with installation, runnable examples, qualified profiles,
and the distinction between a completed comparison and a policy PASS.

New issues and pull requests receive additive type and area labels. The bot
preserves existing labels and executes only trusted default-branch code for
fork pull requests.

## Release verification

Required checks include the combined test suite, individual core/component
suites, line and branch coverage gates, Ruff, mypy, CodeQL, dependency audits,
and distribution-content checks. The release workflow clean-installs both the
wheel and source archive on Linux with every supported Python version, plus
Windows and macOS. Installed-package checks exercise SDK imports, CLI commands,
all three synthetic demo outcomes, and pilot-record persistence outside the
source checkout.

Historical qualification records keep their original runtime, model, device,
and source pins. This patch does not expand native qualification. Positive FP8
KV-cache qualification still requires supported hardware; external participant
feedback remains separate from maintainer and automated validation.
