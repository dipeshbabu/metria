# Metria 0.1.6

This Alpha release adds a qualified FP8 KV-cache verification profile for vLLM
and retains native evidence for the staged trajectory-KLD and vLLM treatment
capabilities. Existing verification profiles, saved-report schemas and method
identities are unchanged.

```sh
python -m pip install metria==0.1.6
metria --version
metria demo --case pass --output demo-pass
```

The base package remains dependency-free and supports Python 3.10–3.14.

## FP8 KV-cache verification

`local_vllm_kv_cache_precision.v1` compares a reference using the model's
automatic KV-cache dtype with a candidate using `fp8`, `fp8_e4m3` or `fp8_e5m2`
on the pinned `vllm==0.30.0+cu129` wheel. Prepare it with:

```sh
metria recipe prepare-vllm --model … --descriptor … --workload tasks.jsonl \
  --policy policy.json --kv-cache-dtype fp8 --output fp8-study.json
metria verify fp8-study.json --output fp8-verification
```

- The engine's own `cache.cache_dtype` must match each request. A contradiction
  fails before measurement; a missing readback is reported as insufficient
  evidence.
- Only the KV-cache dtype may differ between runs, and prefix caching is off.
- Task checks and an acceptance policy are required, so a completed comparison
  always ends PASS or FAIL.

A complete run on an NVIDIA L4 (compute capability 8.9) is retained: FP8 applied,
the comparison was valid, and the policy failed because the public pilot
workload fails identically in the reference. Older GPUs cannot run the pinned
engine's FP8 cache path. See [FP8 KV-cache verification](../guides/fp8-kv-cache-verification.md).

## Staged capabilities: native evidence

These remain staged (no verify profile or policy target uses them), now with
retained native runs:

- **Trajectory KL divergence** on Qwen2.5-0.5B: a self-comparison of exactly
  zero, and `q8_0`/`q4_0` KV-cache changes ranked the same way as an independent
  `llama-perplexity` corpus KLD. Staged captures run through the study lifecycle
  only with the new `metria.staged_captures` capability override.
- **vLLM `vllm.scheduler` and `vllm.cache_layout`** read back as applied on both
  the L4 (CUDA) and CPU wheels; an invalid scheduler budget is rejected by the
  engine at launch.

See [staged capabilities](../guides/staged-capabilities.md).
