# Metria 0.1.4

This Alpha patch release fixes evidence handling in isolated vLLM verification,
artifact-cache downloads, top-k KL scoring and task-check validation.
Verification profiles, saved-report schemas, and numerical method identities
retain their existing scope.

```sh
python -m pip install metria==0.1.4
metria --version
metria demo --case pass --output demo-pass
```

The base package remains dependency-free and supports Python 3.10–3.14. Native
backend extras and the development workspace require Python 3.11 or newer.

## Fixes

- An isolated vLLM verification worker that leaves an unreadable run record, or
  one requested by a different recipe, now produces a complete
  `EXECUTION_FAILED` bundle with exit status `5`. The untrusted file is retained
  as `<role>.run.json.invalid` for inspection and never stands in for the run
  record. Previously the supervisor raised, published no `verification.json`,
  and exited `2` as an invalid configuration.
- Concurrent artifact downloads preserve a competing cache entry: matching
  content is verified and reused, invalid content is rejected, and existing links
  are retained rather than replaced.
- Top-k KL divergence is computed in log space, so extreme but finite
  probabilities remain scoreable. Token chunk allocation is bounded by the
  requested number of chunks.
- Conversion receipt home paths expand consistently, and dangling receipt links
  are rejected before native conversion. Invalid or overflowing download and
  conversion deadlines are reported as input errors.
- Strict JSON-object task checks reject outputs whose numeric exponents decode to
  infinity, including nested values.

## Maintenance

Every script lock is audited and citation metadata is schema-validated in CI.
Package author metadata no longer includes a personal account name.

## Scope

Historical qualification records keep their original runtime, model, device,
and source pins. This patch does not expand native qualification. Positive FP8
KV-cache qualification still requires SM89 or newer hardware; see
[FP8 qualification status](../guides/fp8-qualification-status.md).

See the [installed workflow](../guides/installed-workflow.md),
[runtime qualification](../guides/runtime-qualification.md), and
