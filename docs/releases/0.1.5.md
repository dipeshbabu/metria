# Metria 0.1.5

This Alpha patch release makes malformed user input fail as invalid input
instead of crashing, and corrects command names in `metria fidelity` help.
Verification profiles, saved-report schemas, method identities, and staged
capability scope are unchanged from 0.1.4.

```sh
python -m pip install metria==0.1.5
metria --version
metria demo --case pass --output demo-pass
```

The base package remains dependency-free and supports Python 3.10–3.14.

## Fixes

- **Oversized integers.** JSON decodes integer literals of any size, and
  checking one beyond the float range raised `OverflowError`. A vLLM prefix,
  serving or runtime-upgrade recipe with such a `verification_timeout_s` crashed
  `metria verify` with a traceback; it now exits `2` as an invalid
  configuration. Staged top-k log probabilities, run timing, serving metrics,
  task-check metrics and trial performance values are rejected the same way.
- **Deeply nested JSON.** Recipes, run records, policies, workloads and pilot
  inputs nested too deeply to parse or validate raised `RecursionError` through
  `recipe`, `inspect`, `compare`, `verify` and `pilot`. They now exit `2` with an
  input error.
- **`metria fidelity` command names.** Help and hints told installed users to
  run the source-only `kv-fidelity` command and install `kv-fidelity[sglang]`.
  They now name `metria fidelity …` and `metria[sglang]`; the source checkout's
  `kv-fidelity` entry point keeps its own name.

## Release verification

Before this release, every CLI command that reads user JSON was exercised with
invalid, empty, BOM-prefixed, non-UTF-8, `NaN`, duplicate-key, oversized-integer,
deeply nested, wrongly typed, directory and missing inputs; none now escapes as
an uncaught exception. All retained qualification recipes still validate and
inspect, every retained recipe digest still matches its verification record,
and every retained reference/candidate pair remains comparable.

Native qualification is unchanged. Positive FP8 KV-cache qualification and the
staged trajectory-KLD and vLLM treatment capabilities still require native runs;
see [staged capabilities](../guides/staged-capabilities.md).
