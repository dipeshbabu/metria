# Metria 0.1.1

This Alpha update keeps the qualified llama.cpp CPU thread-change workflow and
makes its evidence more useful for an engineering decision:

- Canonical `verification.json`, deterministic Markdown, and stable CI exit codes
  distinguish execution, evidence, comparability, and explicit policy acceptance.
- Behavioral diagnostics identify divergence counts, positions, categories, and
  prompt fingerprints without placing raw prompts in the summary.
- Compatible native cold-process latency remains separate from steady-state
  serving metrics; TTFT, decode throughput, and device/KV memory stay unavailable.
- Shared artifact/provenance contracts support immutable model/data identity and
  the independently released KV Fidelity component.
- Real pinned vLLM CPU and CUDA adapter qualification is retained as evidence.
  It does not expand `metria verify` beyond its qualified llama.cpp CPU scope.
- Reusable reporting, numerical, and diagnostic boundaries carry independent
  coverage gates and documented complexity limits.
- Research trial utilities reuse the verifier, retain warmup/measured evidence,
  and compare baseline eligibility only under matching artifact, workload,
  hardware, method, and implementation identity.

After publication, install with Python 3.10–3.14:

```bash
python -m pip install metria==0.1.1
metria --version
```

The root wheel retains zero runtime dependencies. Prepare the native provider and
model separately using the [local verifier guide](../guides/metria-verify.md).
Core/install CI covers Linux, Windows, and macOS; real-engine evidence names its
specific OS, runtime revision, model artifacts, and hardware.

Compatibility: `manifest.json` remains an alias for the canonical result. Recipes
for this CLI must declare exactly the four qualified thread-change paths and no
comparison waivers; regenerate older broad variation declarations with the recipe
preparation tool. Exit codes are documented in the [CI guide](../guides/verification-ci.md).
Unsupported runtime upgrades, KV precision, and quantization recipes remain staged.

`VERIFIED` establishes a completed valid comparison and analysis. `PASS`/`FAIL`
require the user's declared policy and do not certify deployment quality or safety.
Run records may contain requested paths or prompt text; review them before sharing.

The publishing workflow verifies artifact hashes, clean installations, and signed
PyPI provenance before creating the GitHub release. See the
[release procedure](../guides/releasing-metria.md).
